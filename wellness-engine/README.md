# wellness-engine

Deterministic wellness calculation engine (Go) ported from the RITMA Flutter
app (noana-org/ritma-app). Reproduces the ritma-app sleep / stress /
readiness / activity scores and baselines EXACTLY for the same input.

**Status:** STAGES 1–8 of the implementation plan
(docs/go-wellness-engine-architecture.md §13) — pure calculation core only.
No HTTP, no database, no device code (Phase 7 constraint). Persistence,
API, versioning and the differential harness are the next stages.

## Layout

```
cmd/wellness-engine/     CLI: day JSON in → scores JSON out
internal/
  domain/                typed core (Measurement, NightSummary, validation)
  config/                versioned parameters (parity with ScoreCalibration)
  stats/                 Dart-parity statistics (round/toInt/median/P10/lerp)
  night/                 F-12 night pipeline (gap-fill, 1h expunge, 16h cap)
  baseline/              F-05/F-06/F-07 baselines (P10, median+shrinkage)
  priors/                F-10 demographic priors
  scoring/sleep/         F-01 sleep score (discount model)
  scoring/stress/        F-02 stress (HRV log-domain, sigmoid)
  scoring/readiness/     F-03 readiness (weighted blend + caps)
  scoring/activity/      F-04 activity (kcal goal, day target, peak counter)
  engine/                day orchestration (pure)
  golden/                oracle loader (docs/golden/oracle.json)
testdata/                example day input
```

## Compatibility oracle

`docs/golden/oracle.json` was generated by executing the REAL Dart algorithm
classes (test/golden_oracle_test.dart, `flutter test` → 5/5). Every scoring
package has golden tests that load it and assert exact parity:

```bash
go test ./...          # all golden tests must pass
```

Tolerance policy (docs/wellness-golden-dataset.md §D): integer scores exact;
doubles relative 1e-9 — including reproduced float artifacts such as
pctLight = 57.99999999999999.

## Usage

```bash
go run ./cmd/wellness-engine -input testdata/example-day.json
# or: cat day.json | go run ./cmd/wellness-engine
```

Input contract: docs/wellness-input-contract.md. The CLI wire format is
documented in cmd/wellness-engine/main.go (inputJSON).

## Known divergences (documented, not "fixed")

- F-01 early-bedtime coefficients are dead code in ritma-app; the dead path
  is preserved (going to bed early never changes the score).
- The sleep-stage raw→canonical mapping conflict (executing mapper 1→Light /
  2→Deep vs the ingestion comment 1=deep/2=light) is NOT resolved by this
  engine — it consumes canonical stages; ingestion-side verification is a
  device task (audit supplementary finding #1).
- Golden pipeline cases N1–N5 and B.2 are hand-derived/verified against the
  executing Dart behavior (case N3 correction: a nightEnd-clamped segment
  yields a degenerate window, not an empty night).
